# 3. Сильные и слабые стороны

## Ruflo
- Сильные: методология агентов (deep-researcher, dossier-investigator), большое сообщество, MIT.
- Слабые: тяжёлый MCP-сервер, бинарный agentdb.rvf (нечитаем), полная установка нецелесообразна.

## ECC
- Сильные: лучший цикл разработки с памятью (remember->improve), 281 навык, огромная популярность.
- Слабые: платная модель ECC Pro, JavaScript (TypeScript-экосистема TT3Dato не совпадает).

## OmniRoute
- Сильные: единственный из четырёх, кто решает экономику LLM (маршрутизация + сжатие до ~89%).
- Слабые: шлюз, а не агентная методология; требует инфраструктуры и настройки.

## Aegis
- Сильные: единственный с trust-доменами и карантином ввода — изоляция клиентских данных при аудите.
- Слабые: ранний MVP (8 коммитов), один автор, риск нестабильности.

# 4. Выводы аудита

1. **Ни один репозиторий не покрывает TT3Dato целиком.** Каждый закрывает свою нишу:
   - Ruflo — методология исследовательских агентов (уже использована);
   - ECC — цикл разработки с памятью;
   - OmniRoute — экономика LLM;
   - Aegis — безопасность и верифицируемая память.
2. **Самая высокая приоритетность для заимствования:** ECC (цикл с памятью) и OmniRoute (экономика LLM).
3. **Самая низкая готовность:** Aegis — наблюдаем, но не внедряем до стабилизации.
4. **Общая рекомендация:** заимствовать методологии/навыки, а не устанавливать тяжёлые зависимости. Это соответствует Конституции TT3Dato (раздел 4, «Open Source First»).
