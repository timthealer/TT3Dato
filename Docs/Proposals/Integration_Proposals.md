# Integration Proposals

**Подготовлено:** Huckleberry Finn (архитектор TT3Dato), 2026-08-01
**Основание:** `Docs/Audits/Comparative_Analysis_Four_Repos.md` + 4 исследовательских отчёта
**Статус:** Ожидает решения пользователя (Decision Protocol, Конституция раздел 6)

---

# 1. Проблема

TT3Dato выполняет массовые AI-операции (аудит компаний, исследования, генерация агентов), которые стоят денег за LLM-токены. Сейчас:

- нет механизма дешёвого доступа к моделям (маршрутизация, сжатие контекста);
- нет формального цикла разработки с памятью (как у ECC);
- нет изоляции данных клиентов при аудите (trust-домены Aegis).

---

# 2. Проблема и кандидаты-решения

По результатам аудита четырёх репозиториев выделены три направления, каждому соответствует свой кандидат.

---

## 2.1. Экономика LLM — кандидат: OmniRoute

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Внедрить OmniRoute как шлюз | ~89% экономии токенов на сжатии; ~1.53B бесплатных токенов/мес; один endpoint | Требует инфраструктуры и настройки; ещё одна внешняя зависимость |
| B. Не внедрять, ждать | Ноль рисков | Расходы на LLM растут с масштабом задач |
| C. Только изучить сжатие контекста (RTK+Caveman) | Минимум зависимостей | Частичная выгода |

Последствия:
- A: существенная экономия на массовых операциях, но рост сложности системы.
- B: простейший путь, но упущенная выгода.
- C: компромисс — заимствовать алгоритм сжатия локально.

## 2.2. Цикл разработки с памятью — кандидат: ECC

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Внедрить полный ECC (CLI/GitHub App) | Готовый цикл plan->test->implement->review->verify->remember->improve; 281 навык | ECC Pro платный; JavaScript; тяжёлая установка |
| B. Заимствовать только цикл и навыки | Лёгкая адаптация под TT3Dato | Больше ручной работы |
| C. Игнорировать | Нет работы | Нет формального «remember -> improve» |

Последствия:
- A: быстро, но противоречит принципу «не изобретать» (тяжёлая чужая платформа).
- B: оптимально для TT3Dato — цикл встроить в рабочие процессы, навыки адаптировать.
- C: отказ от улучшения процесса на основе памяти.

## 2.3. Безопасность и изоляция данных — кандидат: Aegis

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Внедрить trust-домены Aegis | Изоляция клиентских данных при аудите; карантин ввода | Ранний MVP (8 коммитов), риск нестабильности |
| B. Наблюдать, внедрить после стабилизации | Ноль рисков; проект может дорасти | Отложенная выгода |
| C. Игнорировать | Нет работы | Нет защиты от prompt injection при работе с внешними данными |

Последствия:
- A: преждевременно — проект может меняться несовместимо.
- B: разумно для раннего проекта; сейчас зафиксировать как кандидата в Agent Registry.
- C: потеря возможности изоляции данных.

---

# 3. Рекомендация Huckleberry Finn

1. **ECC (цикл)** — заимствовать методологию сейчас: встроить `plan -> test -> implement -> review -> verify -> remember -> improve` в рабочие процессы TT3Dato. Это прямое соответствие Конституции (раздел 11, саморазвитие). Без платной установки.
2. **OmniRoute (экономика)** — рекомендую оценить внедрение в качестве шлюза для массовых LLM-операций. Высокая экономия (~89% на сжатии) окупает настройку.
3. **Aegis (безопасность)** — внести в реестр кандидатов (Agent Registry / Candidate Repositories) с пометкой «наблюдение до стабилизации». Не внедрять в MVP.

---

# 4. Решение пользователя

Ожидается подтверждение по каждому из трёх направлений (внедрять / заимствовать / наблюдать / игнорировать). Без решения пользователя изменения не выполняются.
