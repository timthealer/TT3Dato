# Git Workflow

## Формат сообщения коммита

```
<type>: <description>

<optional body>
```

Типы: feat, fix, refactor, docs, test, chore, perf, ci

Соглашения TT3Dato:

- Сообщения коммитов пишутся на английском, описание тела — по необходимости.
- Перед коммитом проверить `git status`, `git diff` и `git log --oneline -10`.
- Не коммитить секреты и лишние файлы; стейджить только намеренные изменения.
- Не менять git-конфиг и не использовать force-push без явного запроса.

## Workflow pull request

При создании PR:

1. Проанализировать всю историю коммитов (не только последний).
2. Использовать `git diff [base-branch]...HEAD`, чтобы увидеть все изменения.
3. Составить полное резюме PR.
4. Включить тест-план с TODO.
5. Пушить с флагом `-u`, если ветка новая.

> Полный процесс разработки (планирование, TDD, ревью) до git-операций см. в `development-workflow.md`.
