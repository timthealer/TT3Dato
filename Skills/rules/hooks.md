# Система hooks

## Типы событий

- **PreToolUse**: перед выполнением инструмента (валидация, модификация параметров);
- **PostToolUse**: после выполнения инструмента (auto-format, проверки);
- **Stop**: когда сессия завершается (финальная верификация).

TT3Dato использует hooks как концепцию детерминированных проверок вне контекста модели. Вместо исполняемого харнесс-кода детерминированные проверки оформляются как workflow-проверки в `Tests/` (см. `Tests/README.md`). Процессные следы записываются в `Logs/` (см. `Logs/README.md`).

## Авто-принятие разрешений

Использовать с осторожностью:

- Включать только для доверенных, чётко определённых планов;
- Отключать для исследовательских задач;
- Никогда не использовать флаг dangerously-skip-permissions;
- Настраивать `allowedTools` в конфигурации инструментов вместо обхода разрешений.

## Лучшие практики TodoWrite

Использовать TodoWrite для:

- Отслеживания прогресса многошаговых задач;
- Проверки понимания инструкций;
- Обеспечения управления в реальном времени;
- Показа детальных шагов реализации.

Список задач (todo list) выявляет:

- Нарушенный порядок шагов;
- Пропущенные пункты;
- Лишние ненужные пункты;
- Неверную гранулярность;
- Неверно понятые требования.

## Роль в evidence trail

Каждый результат агента сопровождается evidence: план, падающий тест, прошедший тест, находки ревью, финальная проверка. Детерминированные проверки из hooks-концепции выполняются вне контекста модели и фиксируются в `Tests/`; процессные логи — в `Logs/`.
