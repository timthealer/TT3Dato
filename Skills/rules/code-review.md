# Стандарты ревью кода

## Назначение

Ревью обеспечивает качество, безопасность и поддерживаемость до слияния кода. Это правило определяет когда и как проводить ревью (Critic Protocol, Конституция, раздел 7).

## Когда ревьюить

**Обязательные триггеры ревью:**

- После написания или изменения кода;
- Перед любым коммитом в общие ветки;
- Когда изменяется код, чувствительный к безопасности (auth, платежи, пользовательские данные);
- Когда вносятся архитектурные изменения;
- Перед слиянием pull request.

**Требования до ревью:**

Перед запросом ревью убедиться, что:

- Все автоматические проверки (CI/CD) проходят;
- Конфликты слияния разрешены;
- Ветка обновлена до состояния целевой ветки.

## Чек-лист ревью

Перед отметкой кода как завершённого:

- [ ] Код читаемый, имена осмысленные
- [ ] Функции сфокусированы (< 50 строк)
- [ ] Файлы связные (< 800 строк)
- [ ] Нет глубокой вложенности (> 4 уровней)
- [ ] Ошибки обрабатываются явно
- [ ] Нет захардкоженных секретов или credentials
- [ ] Нет console.log и debug-выражений
- [ ] Для новой функциональности есть тесты
- [ ] Покрытие тестами не менее 80%

## Триггеры ревью безопасности

**STOP и использовать агент `security-reviewer`, когда:**

- Код аутентификации или авторизации;
- Обработка пользовательского ввода;
- Запросы к базе данных;
- Операции с файловой системой;
- Внешние API-вызовы;
- Криптографические операции;
- Платёжный или финансовый код.

## Уровни серьёзности ревью

| Level | Значение | Действие |
|-------|----------|----------|
| CRITICAL | Уязвимость безопасности или риск потери данных | **BLOCK** — исправить до слияния |
| HIGH | Баг или значимая проблема качества | **WARN** — желательно исправить до слияния |
| MEDIUM | Проблема поддерживаемости | **INFO** — рассмотреть исправление |
| LOW | Стиль или мелкое предложение | **NOTE** — опционально |

## Использование агентов

Для ревью использовать подходящих агентов:

| Agent | Назначение |
|-------|------------|
| **code-reviewer** | Общее качество кода, паттерны, лучшие практики |
| **security-reviewer** | Уязвимости безопасности, OWASP Top 10 |
| **typescript-reviewer** | Проблемы TypeScript/JavaScript |
| **python-reviewer** | Проблемы Python |
| **go-reviewer** | Проблемы Go |
| **rust-reviewer** | Проблемы Rust |

## Процесс ревью

```
1. Выполнить git diff, чтобы понять изменения
2. Сначала проверить security-чек-лист
3. Проверить чек-лист качества кода
4. Запустить релевантные тесты
5. Подтвердить покрытие >= 80%
6. Использовать подходящего агента для детального ревью
```

## Типовые проблемы

### Безопасность

- Захардкоженные credentials (API-ключи, пароли, токены);
- SQL-инъекции (конкатенация строк в запросах);
- XSS-уязвимости (неэкранированный пользовательский ввод);
- Path traversal (несанитизированные пути файлов);
- Отсутствие защиты CSRF;
- Обходы аутентификации.

### Качество кода

- Большие функции (> 50 строк) — разбить на меньшие;
- Большие файлы (> 800 строк) — выделить модули;
- Глубокая вложенность (> 4 уровней) — использовать early returns;
- Отсутствие обработки ошибок — обрабатывать явно;
- Мутационные паттерны — предпочитать immutable-операции;
- Отсутствие тестов — добавить покрытие.

### Производительность

- N+1 запросы — использовать JOINs или батчинг;
- Отсутствие пагинации — добавить LIMIT к запросам;
- Неограниченные запросы — добавить ограничения;
- Отсутствие кэширования — кэшировать дорогие операции.

## Критерии одобрения

- **Approve**: нет проблем CRITICAL или HIGH;
- **Warning**: есть только проблемы HIGH (сливать с осторожностью);
- **Block**: найдены проблемы CRITICAL.
