# Orchestration агентов

## Доступные агенты

Агенты TT3Dato регистрируются в `Docs/Agent Registry` (Конституция, раздел 5). Запрещается создавать или подключать нового агента без записи в реестре.

| Agent | Назначение | Когда использовать |
|-------|------------|--------------------|
| Huckleberry Finn | Архитектор системы, главный агент | Все задачи по развитию TT3Dato |
| Researcher | Глубокое исследование репозиториев и компаний | Сбор данных, анализ альтернатив |
| Auditor | Аудит компаний, процессов и кода | Оценка, проверка, критика |
| planner | Планирование реализации | Сложные фичи, рефакторинг |
| architect | Системное проектирование | Архитектурные решения |
| tdd-guide | Разработка через тесты (TDD) | Новые фичи, исправления багов |
| code-reviewer | Ревью кода | Сразу после написания кода |
| security-reviewer | Анализ безопасности | Перед коммитами |
| doc-updater | Обновление документации | Изменение документации |

## Немедленное использование агентов

Без запроса пользователя:

1. Сложный запрос на фичу — использовать агент `planner`.
2. Код только что написан или изменён — использовать агент `code-reviewer`.
3. Исправление бага или новая фича — использовать агент `tdd-guide`.
4. Архитектурное решение — использовать агент `architect`.

## Параллельное выполнение задач

Всегда использовать параллельное выполнение независимых операций:

```markdown
# ХОРОШО: параллельное выполнение
Запустить 3 агентов параллельно:
1. Agent 1: анализ безопасности модуля auth
2. Agent 2: ревью производительности кэша
3. Agent 3: проверка типов утилит

# ПЛОХО: последовательно, когда параллельность нужна
Сначала агент 1, потом агент 2, потом агент 3
```

## Контракт завершения делегирования

Применяется к каждому агенту на любом уровне вложенности (родитель, ребёнок, внук):

1. **Ваше финальное сообщение и есть результат.** Никогда не завершать ход со словами «ожидаю фоновых агентов» — порождённая задача не является завершённой задачей. Завершение хода при работающих детях теряет их результаты (завершившиеся дети не могут уведомить родителя, чей ход уже закончен).
2. **Если вы делегировали — вы отвечаете за сбор.** Дождаться результатов, интегрировать их, вернуть ответ. Делегирование в режиме fire-and-forget запрещено.
3. **Декомпозировать только тогда, когда работа не помещается в один контекст.** Не ределегировать задачу, рассчитанную на одного агента — глубина это результат, а не план.

> Обоснование: наблюдаемый сбой — исследовательские агенты порождали детей и возвращали «ожидание» как финальный ответ. Все дети завершались успешно, но их результаты терялись. Правило параллельности без контракта завершения порождает zombie-задачи.

## Многоперспективный анализ

Для сложных проблем использовать субагентов с разделёнными ролями:

- Factual reviewer
- Senior engineer
- Security expert
- Consistency reviewer
- Redundancy checker
