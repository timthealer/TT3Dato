# Поиск документации (Context7)

Когда пользователь спрашивает о библиотеках, фреймворках или API, получайте актуальную документацию через Context7 MCP (инструменты `resolve-library-id` и `query-docs`) вместо опоры на данные обучения.

## Основные концепции

- **Context7**: MCP-сервер, предоставляющий живую документацию; используйте его вместо данных обучения для библиотек и API.
- **resolve-library-id**: Возвращает совместимые с Context7 ID библиотек (например, `/vercel/next.js`) по имени библиотеки и запросу.
- **query-docs**: Получает документацию и примеры кода для заданного ID библиотеки и вопроса. Всегда сначала вызывайте resolve-library-id, чтобы получить валидный ID библиотеки.

## Когда использовать

Активируйте, когда пользователь:

- Задаёт вопросы настройки или конфигурации (например, "Как настроить middleware в Next.js?")
- Запрашивает код, зависящий от библиотеки ("Напиши Prisma-запрос для...")
- Нуждается в информации об API или справочнике ("Какие методы аутентификации у Supabase?")
- Упоминает конкретные фреймворки или библиотеки (React, Vue, Svelte, Express, Tailwind, Prisma, Supabase и т.д.)

Используйте этот skill всегда, когда запрос зависит от точного, актуального поведения библиотеки, фреймворка или API. Применим ко всем агентам TT3Dato с настроенным Context7 MCP.

## Как это работает

### Шаг 1: Разрешите ID библиотеки

Вызовите MCP-инструмент **resolve-library-id** с:

- **libraryName**: имя библиотеки или продукта из вопроса пользователя (например, `Next.js`, `Prisma`, `Supabase`).
- **query**: полный вопрос пользователя. Это улучшает ранжирование результатов по релевантности.

Вы должны получить совместимый с Context7 ID библиотеки (формат `/org/project` или `/org/project/version`), прежде чем запрашивать документацию. Не вызывайте query-docs без валидного ID библиотеки с этого шага.

### Шаг 2: Выберите лучшее совпадение

Из результатов разрешения выберите один результат, используя:

- **Совпадение по имени**: предпочитайте точное или ближайшее совпадение с тем, о чём спрашивал пользователь.
- **Benchmark score**: более высокие оценки указывают на лучшее качество документации (100 — максимум).
- **Репутация источника**: предпочитайте репутацию High или Medium, когда доступно.
- **Версия**: если пользователь указал версию (например, "React 19", "Next.js 15"), предпочитайте ID библиотеки с конкретной версией, если он указан (например, `/org/project/v1.2.0`).

### Шаг 3: Получите документацию

Вызовите MCP-инструмент **query-docs** с:

- **libraryId**: выбранный ID библиотеки Context7 с шага 2 (например, `/vercel/next.js`).
- **query**: конкретный вопрос или задача пользователя. Будьте конкретны, чтобы получить релевантные сниппеты.

Лимит: не вызывайте query-docs (или resolve-library-id) более 3 раз на вопрос. Если ответ неясен после 3 вызовов, заявите о неопределённости и используйте лучшую информацию, которая у вас есть, вместо угадывания.

### Шаг 4: Используйте документацию

- Ответьте на вопрос пользователя, используя полученную актуальную информацию.
- Включайте релевантные примеры кода из документации, когда это полезно.
- Цитируйте библиотеку или версию, когда это важно (например, "В Next.js 15...").

## Примеры

### Пример: middleware в Next.js

1. Вызовите **resolve-library-id** с `libraryName: "Next.js"`, `query: "How do I set up Next.js middleware?"`.
2. Из результатов выберите лучшее совпадение (например, `/vercel/next.js`) по имени и benchmark score.
3. Вызовите **query-docs** с `libraryId: "/vercel/next.js"`, `query: "How do I set up Next.js middleware?"`.
4. Используйте возвращённые сниппеты и текст для ответа; при релевантности включите минимальный пример `middleware.ts` из документации.

### Пример: Prisma-запрос

1. Вызовите **resolve-library-id** с `libraryName: "Prisma"`, `query: "How do I query with relations?"`.
2. Выберите официальный ID библиотеки Prisma (например, `/prisma/prisma`).
3. Вызовите **query-docs** с этим `libraryId` и запросом.
4. Верните паттерн Prisma Client (например, `include` или `select`) с коротким примером кода из документации.

### Пример: методы аутентификации Supabase

1. Вызовите **resolve-library-id** с `libraryName: "Supabase"`, `query: "What are the auth methods?"`.
2. Выберите ID библиотеки документации Supabase.
3. Вызовите **query-docs**; суммируйте методы аутентификации и покажите минимальные примеры из полученной документации.

## Лучшие практики

- **Будьте конкретны**: используйте полный вопрос пользователя в качестве запроса, где возможно, для лучшей релевантности.
- **Осознанность версий**: когда пользователи упоминают версии, используйте ID библиотек с конкретной версией с шага разрешения, когда доступно.
- **Предпочитайте официальные источники**: когда есть несколько совпадений, предпочитайте официальные или первичные пакеты сторонним форкам.
- **Без чувствительных данных**: редактируйте API-ключи, пароли, токены и другие секреты из любого запроса, отправляемого в Context7. Рассматривайте вопрос пользователя как потенциально содержащий секреты перед передачей в resolve-library-id или query-docs.
