# Конструирование обвязки агента (Agent Harness Construction)

Используйте этот skill, когда улучшаете то, как агент планирует, вызывает инструменты, восстанавливается после ошибок и сходится к завершению.

## Основная модель

Качество вывода агента ограничено:
1. Качеством пространства действий (action space)
2. Качеством наблюдений (observation)
3. Качеством восстановления (recovery)
4. Качеством контекстного бюджета

## Проектирование пространства действий

1. Используйте стабильные, явные имена инструментов.
2. Держите входные данные schema-first и узкими.
3. Возвращайте детерминированные формы вывода.
4. Избегайте catch-all инструментов, если изоляция невозможна.

## Правила гранулярности

- Используйте микро-инструменты для высокорисковых операций (deploy, миграция, права доступа).
- Используйте средние инструменты для обычных циклов edit/read/search.
- Используйте макро-инструменты только когда накладные расходы на round-trip — доминирующая стоимость.

## Проектирование наблюдений

Каждый ответ инструмента должен включать:
- `status`: success|warning|error
- `summary`: однострочный результат
- `next_actions`: действенные follow-up'ы
- `artifacts`: пути файлов / ID

## Контракт восстановления после ошибок

Для каждого пути ошибки включите:
- подсказку о корневой причине (root cause hint)
- безопасную инструкцию повтора (safe retry instruction)
- явное условие остановки (explicit stop condition)

## Управление контекстным бюджетом

1. Держите системный промпт минимальным и инвариантным.
2. Выносите большие руководства в skills, загружаемые по требованию.
3. Предпочитайте ссылки на файлы вместо встраивания длинных документов.
4. Уплотняйте на границах фаз, а не на произвольных порогах токенов.

## Рекомендации по архитектурным паттернам

- ReAct: лучше всего для исследовательских задач с неопределённым путём.
- Function-calling: лучше всего для структурированных детерминированных потоков.
- Hybrid (рекомендуется): планирование ReAct + типизированное выполнение инструментов.

## Бенчмаркинг

Отслеживайте:
- completion rate
- повторы на задачу
- pass@1 и pass@3
- стоимость за успешную задачу

## Анти-паттерны

- Слишком много инструментов с перекрывающейся семантикой.
- Непрозрачный вывод инструментов без подсказок восстановления.
- Вывод только об ошибке без следующих шагов.
- Перегрузка контекста нерелевантными ссылками.
