# Context Budget

Анализируйте накладные расходы на токены по каждому загруженному компоненту в сессии агента TT3Dato и предлагайте действенные оптимизации для возврата контекстного пространства.

## Когда использовать

- Производительность сессии кажется вялой или качество вывода деградирует
- Вы недавно добавили много skills, агентов или MCP-серверов
- Вы хотите узнать, сколько контекстного запаса у вас на самом деле
- Планируете добавить больше компонентов и нужно узнать, есть ли место
- Запуск команды `/context-budget` (этот skill её поддерживает)

## Как это работает

### Фаза 1: Инвентаризация

Просканируйте все каталоги компонентов и оцените потребление токенов:

**Агенты** (`Agents/*.md`)
- Считайте строки и токены на файл (слова × 1.3)
- Извлеките длину описания `description` из frontmatter
- Помечайте: файлы >200 строк (тяжёлые), description >30 слов (раздутый frontmatter)

**Skills** (`Skills/*/SKILL.md`)
- Считайте токены каждого SKILL.md
- Помечайте: файлы >400 строк
- Проверяйте дубликаты копий в `Skills/` — пропускайте идентичные копии, чтобы не считать дважды

**Правила (rules)** (`rules/**/*.md` или `Docs/rules/`)
- Считайте токены каждого файла
- Помечайте: файлы >100 строк
- Обнаруживайте перекрытие содержимого между файлами правил в одном языковом модуле

**MCP-серверы** (`.mcp.json` или активная конфигурация MCP)
- Считайте настроенные серверы и общее количество инструментов
- Оценивайте накладные расходы на схемы примерно в ~500 токенов на инструмент
- Помечайте: серверы с >20 инструментами, серверы, оборачивающие простые CLI-команды (`gh`, `git`, `npm`, `supabase`, `vercel`)

**Руководящие файлы (CLAUDE.md)** (проектный + пользовательский уровень)
- Считайте токены каждого файла в цепочке руководящих файлов
- Помечайте: суммарно >300 строк

### Фаза 2: Классификация

Отсортируйте каждый компонент в корзину:

| Корзина | Критерий | Действие |
|--------|----------|----------|
| **Всегда нужны** | Упоминаются в руководящем файле, поддерживают активную команду или соответствуют текущему типу проекта | Оставить |
| **Иногда нужны** | Доменно-специфичны (например, языковые паттерны), не упоминаются в руководящем файле | Рассмотреть активацию по требованию |
| **Редко нужны** | Нет ссылки на команду, перекрывающееся содержимое или нет очевидного соответствия проекту | Удалить или lazy-load |

### Фаза 3: Обнаружение проблем

Выявите следующие проблемные паттерны:

- **Раздутые описания агентов** — description >30 слов в frontmatter загружается в каждый вызов Task-инструмента
- **Тяжёлые агенты** — файлы >200 строк раздувают контекст Task-инструмента при каждом запуске
- **Избыточные компоненты** — skills, дублирующие логику агентов, правила, дублирующие руководящий файл
- **Переподписка на MCP** — >10 серверов, или серверы, оборачивающие CLI-инструменты, доступные бесплатно
- **Раздутый руководящий файл** — многословные объяснения, устаревшие разделы, инструкции, которые должны быть правилами

### Фаза 4: Отчёт

Составьте отчёт о контекстном бюджете:

```
Context Budget Report
═══════════════════════════════════════

Total estimated overhead: ~XX,XXX tokens
Context model: Claude Sonnet (200K window)
Effective available context: ~XXX,XXX tokens (XX%)

Component Breakdown:
┌─────────────────┬────────┬───────────┐
│ Component       │ Count  │ Tokens    │
├─────────────────┼────────┼───────────┤
│ Agents          │ N      │ ~X,XXX    │
│ Skills          │ N      │ ~X,XXX    │
│ Rules           │ N      │ ~X,XXX    │
│ MCP tools       │ N      │ ~XX,XXX   │
│ CLAUDE.md       │ N      │ ~X,XXX    │
└─────────────────┴────────┴───────────┘

WARNING: Issues Found (N):
[ranked by token savings]

1. [action] → save ~X,XXX tokens
2. [action] → save ~X,XXX tokens

```

В подробном (verbose) режиме дополнительно выводите пофайловый подсчёт токенов, построчный разбор самых тяжёлых файлов, конкретные избыточные строки между перекрывающимися компонентами и список MCP-инструментов с оценкой размера схемы каждого инструмента.

## Примеры

**Базовый аудит**
```
Пользователь: /context-budget
Skill: Сканирует настройку → 16 агентов (12,400 токенов), 28 skills (6,200), 87 MCP-инструментов (43,500), 2 руководящих файла (1,200)
       Помечает: 3 тяжёлых агента, 14 MCP-серверов (3 заменяемых CLI)
       Топ-экономия: удалить 3 MCP-сервера → -27,500 токенов (47% снижение накладных расходов)
```

**Verbose режим**
```
Пользователь: /context-budget --verbose
Skill: Полный отчёт + пофайловый разбор, показывающий planner.md (213 строк, 1,840 токенов),
       список MCP-инструментов с размерами каждого, дублирующиеся строки правил рядом
```

**Проверка перед расширением**
```
Пользователь: Хочу добавить ещё 5 MCP-серверов, есть ли место?
Skill: Текущие накладные расходы 33% → добавление 5 серверов (~50 инструментов) добавит ~25,000 токенов → поднимет накладные расходы до 45%
       Рекомендация: сначала удалить 2 заменяемых CLI сервера, чтобы остаться ниже 40%
```

## Лучшие практики

- **Оценка токенов**: используйте `слова × 1.3` для прозы, `символы / 4` для файлов с большим количеством кода
- **MCP — самый большой рычаг**: схема каждого инструмента стоит ~500 токенов; сервер с 30 инструментами стоит дороже, чем все ваши skills вместе взятые
- **Описания агентов загружаются всегда**: даже если агент никогда не вызывается, его поле description присутствует в каждом контексте Task-инструмента
- **Verbose режим для отладки**: используйте, когда нужно точно указать файлы, создающие накладные расходы, а не для регулярных аудитов
- **Аудит после изменений**: запускайте после добавления любого агента, skill или MCP-сервера, чтобы рано выявлять разрастание
