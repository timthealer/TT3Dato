# Workflow: обработка Telegram Inbox

Кто исполняет: **HuckleberryFinn** (при запуске владельцем).

## Цель

Не оставлять `Telegram/inbox/` складом заметок: каждое сообщение осмысляется, классифицируется и укладывается в структуру TT3Dato. При неясности — уточнить у владельца через HuckleberryFinnBot (sendMessage на `OWNER_CHAT_ID`).

## Шаги

1. **Собрать новые записи.** Прочитать свежие файлы `Telegram/inbox/YYYY-MM-DD.md`, которые ещё не обработаны (следить по `Telegram/_PROCESSED.md`).

2. **Классифицировать каждую запись:**
   - идея → `Docs/Ideas/` или `Blueprint/`;
   - задача/поручение → `Docs/Tasks/`;
   - вопрос к владельцу → задать сразу;
   - факт о себе/проектах → `Memory/unverified/`;
   - файл-загрузка → уже лежит в `Don'tReadMe/`, отметить в `Don'tReadMe/_PROCESSED.md`.

3. **Неясно? Уточнить.** Если тип, принадлежность или суть неоднозначны — сформировать один короткий вопрос и отправить через бота:
   `sendMessage chat_id=5255559756 text=...`. Не гадать.

4. **Разложить.** Записать осмысленную заметку в целевую папку (связь с контекстом, атрибуция времени, источник `Telegram/inbox`).

5. **Отметить обработанное** в `Telegram/_PROCESSED.md`, чтобы не перечитывать.

## Канал «заметки на ходу»

Записи «на ходу» (за рулём) — голосовые/короткие тексты: расшифровку и осмысление делает HuckleberryFinn, уточнения задаёт одним сообщением, далее сортирует по правилам выше.

## Правила

- Один вопрос за раз, без простыней.
- Не обрабатывать `Don'tReadMe/` целиком без задачи владельца (см. README этой папки).
- Каждая заметка — с датой и источником, по политике ecc.memory.v1 (unverified → verified после подтверждения).
