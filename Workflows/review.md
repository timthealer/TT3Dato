# Review Workflow

> Источник методологии: https://github.com/affaan-m/ECC (MIT, `workflows/orch-review.workflow.js` + агент code-reviewer). Адаптировано для TT3Dato.

Оркестрация критического анализа (агент CodeReviewer). Реализует шаг `review` цикла Конституции (раздел 15) и Critic Protocol (раздел 7).

## Шаги

### 1. Сбор контекста

- Получить изменения: `git diff`, `git log`;
- Прочитать окружающий код/документы (не review в изоляции).

### 2. Анализ

- Искать: ошибки, слабые места, альтернативы, попытки опровержения (Critic Protocol);
- Находки только с уверенностью выше 80%;
- Объединять похожие проблемы в одну.

### 3. Классификация

| Severity | Значение | Действие |
|---|---|---|
| CRITICAL | Блокирующая ошибка/безопасность | Block |
| HIGH | Серьёзная проблема | Block/Warning |
| MEDIUM | Умеренная проблема | Warning |
| LOW | Незначительная проблема | Approve/Warning |

Каждая находка HIGH/CRITICAL требует доказательств: точная строка, сценарий отказа, почему существующие guards не срабатывают.

### 4. Вердикт

- Approve — одобрить;
- Warning — одобрить с замечаниями;
- Block — отправить на доработку.

### 5. Verify

- Проверить, что все CRITICAL/HIGH закрыты до merge;
- Прогнать детерминированные проверки (build, lint, tests).

### 6. Remember

- Сохранить findings и вердикт в `Memory/`;
- Артефакт ревью в `Workflows/reviews/`.

### 7. Improve

- Обновить правила ревью (`Skills/rules/code-review.md`) по опыту.

## Особенности

- Пустой review — валидный результат (не выдумывать findings);
- Не сообщать стилистические предпочтения, если они не нарушают конвенции;
- Чистый diff без CRITICAL/HIGH — одобрять (Approve).
