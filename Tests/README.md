# Tests — Evidence Trail (детерминированные проверки)

Каталог `/workspace/Tests/` — хранилище детерминированных проверок TT3Dato, адаптированное из концепции hooks ECC. Вместе с `Logs/` реализует стандарт «следа доказательств» (evidence trail) цикла `plan -> test -> implement -> review -> verify -> remember -> improve` (Конституция, раздел 15).

## Назначение

`Tests/` — это проверки, которые выполняются **вне контекста модели** и дают воспроизводимый, детерминированный результат. В ECC эту роль выполняют hooks (скрипты на событиях харнесса); TT3Dato оформляет их как локальные workflow-проверки без харнесс-кода.

Проверки подтверждают:

- Структуру репозитория (наличие каталогов и файлов);
- Соответствие документов шаблонам (например, записи памяти формату `ecc.memory.v1`);
- Отсутствие секретов в конфигурационных файлах;
- Соответствие правилам (например, регистрация агентов в `Docs/Agent Registry`);
- Детерминированные инварианты проекта (консистентность ссылок, отсутствие дублей).

## Что здесь находится

- Исполняемые проверки (скрипты, тест-кейсы) с однозначным результатом PASS/FAIL;
- Фикстуры и входные данные проверок;
- Отчёты о прохождении проверок.

## Правило evidence trail

Каждая задача подтверждается цепочкой evidence:

1. **План** — что собирались сделать (лог в `Logs/`);
2. **Падающий тест** — проверка, которая не проходит до реализации;
3. **Прошедший тест** — та же проверка после реализации;
4. **Находки ревью** — зафиксированные в `Logs/`;
5. **Финальная проверка** — полный прогон детерминированных проверок.

## Отличие Tests/ от Logs/

| Каталог | Назначение | Формат |
|---|---|---|
| `Tests/` | Детерминированные проверки вне контекста модели | Воспроизводимые проверки с PASS/FAIL |
| `Logs/` | Процессные следы: планы, отчёты, ревью | Свободный Markdown, см. `Logs/README.md` |

## Правила ведения

- Каждая проверка должна быть воспроизводимой: фиксированный вход, однозначный выход.
- Проверки выполняются локально, вне контекста модели (аналог hooks ECC).
- Результат фиксируется в отчёте (`Logs/` при необходимости).
- Проверки не модифицируют проверяемые данные.
