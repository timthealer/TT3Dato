# Порядок работы над задачей

## 1. Понять задачу

- Прочитай запрос пользователя и, при необходимости, связанные файлы.
- Уточни требования, если они неоднозначны (пользователь любит кнопочные
  подтверждения и предложения вариантов).

## 2. Найти затронутые места

- Поиск по `src/` через grep/glob. Проследи, где находятся типы, логика,
  хранение и экраны, чтобы изменения были согласованы.

## 3. Внести изменения

- Минимальные и по существующим паттернам.
- Интерфейс — русский. Ключи — никогда не хардкодить.
- Если меняется `Settings` — проверь миграцию в `src/storage.ts`
  (пользователи могут хранить старый формат в localStorage).

## 4. Проверить

- Обязательно: `npm run build && npm run lint`.
- Если менялась логика сети/провайдеров — проверь на живой странице через
  dev-сервер, при необходимости curl запросы через прокси `/v1`.

## 5. Показать результат

- Кратко опиши, что изменено, и как пользователь может это проверить
  (например, ссылка на превью).
- Не коммить без явной просьбы пользователя.

## 6. Коммит

- Только после явного одобрения пользователя, по правилу `04-commit.md`.
